Why route a canary probe instead of letting all traffic hit the recovering service at once?

If the half-open cooldown timer expires, why not just reset immediately to CLOSED? What happens if downstream service is still struggling under spike traffic? Great question, Marcus! If you immediately reset to CLOSED, you trigger a classic thundering herd problem. Thousands of concurrent queued requests flood the fragile downstream service, causing immediate cascade failure. A single canary probe tests actual service health safely:

circuit-breaker.ts 
// State transition safety rule with single canary probe
if (canaryResponse.status === 200 && canaryResponse.latency < 50) {
  circuit.tripClosed(); // safe to resume 100% flow
} else {
  circuit.tripOpen();   // back to quarantine for 30s
  metrics.increment('circuit.canary_failure');
}

For multi-region architectures, a phased canary (10% → 50%) is indeed used at the API gateway layer, but in the microservice-to-cache layer (our focus here), single probe health checks minimize connection pool starvation.
